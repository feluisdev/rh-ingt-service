## 1. Visão Geral e Padrões

Este documento detalha as propriedades, comportamentos e validações de todos os formulários e componentes de dados do SIGDI, servindo como guia para a implementação em **React Hook Form + Zod** e componentes do **IGRP UI**.

### 1.1. Tipos de Componentes Padrão

* **`IGRPText`**: Input de texto simples.

* **`IGRPTextArea`**: Área de texto redimensionável.

* **`IGRPRichText`**: Editor WYSIWYG (TipTap/Quill) para textos formatados.

* **`IGRPSelect`**: Dropdown com suporte a busca e async loading.

* **`IGRPCurrency`**: Input numérico com máscara de moeda (CVE/Escudos).

* **`IGRPDatePicker`**: Seletor de data com validação de range.

* **`IGRPSwitch`**: Toggle booleano.

## 2. Módulo Estratégico (Strategy)

### 2.1. Formulário: Identidade Institucional

* **Endpoint:** `POST /v1/strategy/identities`

* **Contexto:** Criação de nova versão (Snapshot) da identidade.

| Label (UI)        | Campo API        | Componente     | Tipo       | Validação (Zod)                          | Comportamento / Regras                            |
| :---------------- | :--------------- | :------------- | :--------- | :--------------------------------------- | :------------------------------------------------ |
| **Missão**        | `mission`        | `IGRPRichText` | `string`   | `min(20, "Mínimo 20 caracteres")`        | Deve permitir bold/italic.                        |
| **Visão**         | `vision`         | `IGRPRichText` | `string`   | `min(20)`                                | Deve permitir bold/italic.                        |
| **Valores**       | `values`         | `TagInput`     | `string[]` | `min(1, "Adicione pelo menos um valor")` | Usuário digita e aperta Enter para adicionar tag. |
| **Justificativa** | `versionComment` | `IGRPText`     | `string`   | `optional`                               | Motivo da alteração (ex: "Revisão 2026").         |

### 2.2. Formulário: Objetivo Estratégico

* **Endpoint:** `POST /v1/strategy/goals`

* **Contexto:** Modal de criação no Mapa BSC.

| Label (UI)     | Campo API     | Componente     | Tipo      | Validação (Zod)    | Comportamento / Regras                                                                    |
| :------------- | :------------ | :------------- | :-------- | :----------------- | :---------------------------------------------------------------------------------------- |
| **Título**     | `title`       | `IGRPText`     | `string`  | `min(5).max(100)`  | Foco inicial automático.                                                                  |
| **Perspetiva** | `perspective` | `IGRPSelect`   | `enum`    | `required`         | Opções fixas: `FINANCIAL`, `CUSTOMER`, `PROCESS`, `LEARNING`. Ícones visuais no dropdown. |
| **Descrição**  | `description` | `IGRPTextArea` | `string`  | `max(500)`         | Opcional.                                                                                 |
| **Peso**       | `weight`      | `IGRPNumber`   | `decimal` | `min(0.1).max(10)` | Default: 1.0. Incremento de 0.1.                                                          |

| :------------------- | :------------------ | :--------------- | :--------- | :------------------------------------------- |

| **Quem (Resp.)**     | `responsible_who`   | `UserSelect`     | `string`   | Busca usuários no Autentika/LDAP.            |
| **Onde (Local)**     | `location_where`    | `IGRPText`       | `string`   | Ex: "Praia", "Online".                       |

#### Passo 3: Orçamento

| Label (UI)         | Campo API            | Componente     | Validação | Comportamento                                                                                                           |
| :----------------- | :------------------- | :------------- | :-------- | :---------------------------------------------------------------------------------------------------------------------- |

| **Status Saldo**   | (Virtual)            | `Badge`        | N/A       | Exibe "Disponível" (Verde) ou "Insuficiente" (Vermelho) baseado na validação.                                           |

## 6. Listagens e Data Grids (Padrão Geral)

Para todas as tabelas (Listagem de Atividades, Histórico de Identidade), usar o componente `GenericDataTable` com as seguintes propriedades padrão:

* **Paginação:** Server-side (`page`, `size`).

* **Ordenação:** Server-side (`sortBy`, `sortDir`). Clique no header da coluna.

* **Estados:**

  * **Loading:** Skeleton de linhas (não apenas spinner).

  * **Empty:** Ilustração SVG + Texto "Sem dados" + Botão de Ação (se aplicável).

  * **Error:** Botão "Tentar Novamente".

### 6.1. Definição de Colunas: Lista PAA

| Header          | Campo Dados        | Renderização                           | Largura    |
| :-------------- | :----------------- | :------------------------------------- | :--------- |

## 7. Critérios de Aceitação de Frontend (DoD)

Para considerar um formulário ou página "Pronto":

1. **Validação:** Todos os campos obrigatórios mostram erro visual se vazios no submit.
2. **Responsividade:** O layout se adapta a Mobile (coluna única) e Desktop (grid/modal).
3. **Loading:** Nenhuma ação assíncrona bloqueia a UI sem feedback visual (spinner/skeleton).
4. **Máscaras:** Campos monetários e datas impedem input de caracteres inválidos.
5. **Acessibilidade:** É possível navegar por todos os campos usando apenas `TAB` e submeter com `ENTER`.
