1.Base, autenticação e cabeçalhos

ItemValor
Base URL (dev)http://localhost:8091 (porta de SERVICE_PORT)
Prefixo/api/v1/rh
Authdevelopment/staging: desligada · production: Authorization: Bearer <JWT> (Keycloak)
CabeçalhosSempre Accept: application/json; em escrita Content-Type: application/json
Sem Accept: application/json alguns clientes recebem XML. Enviar sempre.

2.Convenções

Paginação e wrapper de lista

{
  "content": [ … ],
  "totalElements": 42, "pageNumber": 0, "pageSize": 20,
  "totalPages": 3, "first": true, "last": false
}

Listas aceitam pagina (0-based) e tamanho (default 20).

Padrões de recurso

OperaçãoForma
GET lista/{recurso} (+ filtros)
GET detalhe/{recurso}/{id}
POST criar/{recurso} → 201
PUT atualizar/{recurso}/{id}
DEL soft delete/{recurso}/{id} (marca is_active=false)
PATCH reactivar.../activate
GET combobox.../combobox → {id,label}

Códigos de estado

CódigoSignificado
200/201OK / criado
400Pedido inválido
404Não encontrado
422Regra de negócio — Lugar ocupado, escalão obrigatório/proibido, mobilidade sem Lugar destino, estado não permitido

4.Lugares — /estrutura/positions

MétodoPathDescrição
GET/positions?unidadeId={id}Lista + dotação/ocupados/vagas
GET/positions/{id}Detalhe
POST/positionsCriar Lugar
PUT/positions/{id}Atualizar
PATCH/positions/{id}/freezeCongelar
DEL/positions/{id}Extinguir

PositionRequestDTO

{
  "numeroLugar": "A-01",
  "jobId": "uuid", "unidadeOrganicaId": "uuid",
  "careerId": "uuid | null",     // null = fora de grelha
  "categoryId": "uuid | null",
  "parentPositionId": "uuid | null",
  "managesUnitId": "uuid | null", // Lugar que dirige uma unidade
  "legalBase": "string | null"
}

PositionResponseDTO inclui nomes resolvidos: jobNome, unidadeNome, careerNome, categoryNome + estado, isActive, foraDeGrelha, ocupado.

6.Registo — POST /funcionarios/registar

Cria funcionário + contrato (opcional) + afectação a um Lugar vago, numa chamada.

{
  "funcionario": { … },
  "contrato": { … },              // opcional
  "afectacao": {
    "positionId": "uuid", "gradeId": "uuid | null",
    "origem": "ADMISSAO", "dataInicio": "YYYY-MM-DD"
  },
  "dadosBancarios": { … },        // opcional
  "dossier": { … }                // opcional
}
// resposta inclui: afectacaoId   (NÃO enquadramentoId)
breaking change O registo já não aceita unidade/cargo/carreira/categoria — derivam do positionId. Ver breaking_change_frontend.html.

Fluxo de admissão via Lugar vago

sequenceDiagram
  participant FE as Frontend
  participant API as RH-Service
  FE->>API: GET /assignments/unidade/{u}/vagas/lista
  API-->>FE: lista de Lugares vagos (com nomes)
  FE->>API: POST /funcionarios/registar { afectacao:{positionId,gradeId,origem:ADMISSAO} }
  API-->>FE: 201 { funcionarioId, afectacaoId }
  Note over API: unidade/cargo/carreira derivam do Lugar
