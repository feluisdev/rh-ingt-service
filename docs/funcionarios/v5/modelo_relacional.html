As tabelas do núcleo RH e como se relacionam. Nota importante: no código as ligações são quase sempre colunas UUID (*_id), não associações de objeto — mas as relações existem e são aqui explicitadas.

1.Convenções do modelo

ConvençãoDescrição
Chave primáriaid UUID em todas as tabelas.
RelaçõesColuna <alvo>_id UUID (ex.: funcionario_id). Sem FK física declarada na maioria — a integridade é garantida na aplicação. Exceção: t_contrato usa @ManyToOne real (FK física para t_funcionario e t_contract_type).
Soft deleteis_active BOOLEAN — registos "apagados" ficam false, não são removidos.
Historização (SCD2)is_current, data_inicio, data_fim — em t_assignment e t_contrato. Uma versão corrente por chave de negócio.
AuditoriaEntidades @Audited (Envers) geram tabela _aud em audit_schema + created_by/at, updated_by/at.
Estado derivado"Provido/Vago" de um Lugar não é coluna — calcula-se das afectações correntes.
estrutura colaboradores carreiras parametrizações shared

2.Vista central: Lugar · Afectação · Funcionário

O triângulo que define o modelo v5. A Afectação é a tabela-ponte que liga a pessoa ao Lugar no tempo, e onde vive o escalão.

Núcleo — t_funcionario ↔ t_assignment ↔ t_position

erDiagram
  t_funcionario ||--o{ t_assignment : "é afectado"
  t_position    ||--o{ t_assignment : "é ocupado por"
  t_assignment  }o--o| t_grade      : "escalão (grade_id)"
  t_assignment  }o--o| t_funcao     : "função (function_id)"
  t_assignment  }o--o| t_assignment : "origem (origin_assignment_id)"
  t_position    }o--|| t_job        : "cargo (job_id)"
  t_position    }o--|| t_unidade_organica : "unidade"
  t_position    }o--o| t_career     : "carreira"
  t_position    }o--o| t_category   : "categoria"
  t_funcionario }o--o| t_worker_state : "estado"
  t_funcionario {
    uuid id PK
    uuid worker_state_id FK
    uuid document_type_id FK
  }
  t_position {
    uuid id PK
    uuid job_id FK
    uuid unidade_organica_id FK
    uuid career_id FK
    uuid category_id FK
    uuid parent_position_id FK
    uuid manages_unit_id FK
    string estado
  }
  t_assignment {
    uuid id PK
    uuid funcionario_id FK
    uuid position_id FK
    uuid grade_id FK
    uuid function_id FK
    uuid origin_assignment_id FK
    string origem
    bool is_current
  }
Índice único parcial: (position_id) WHERE is_current garante um ocupante por Lugar; (funcionario_id) WHERE is_current AND assignment_type='PRINCIPAL' garante uma afectação principal por pessoa.

TabelaMóduloPapel · FKs
t_leave_requestcolaboradoresPedido de ausência. tipo_ausencia_id→t_leave_type. Fluxo aprovar/rejeitar/cancelar.
t_leave_balancecolaboradoresSaldo por funcionário e tipo de ausência.
t_leave_mobilitycolaboradoresLicença/mobilidade. subtipo_id, destination_unit_id, destination_position_id (Lugar de destino), document_id.
MOBILIDADE aprovada cria uma afectação no destination_position_id (via AssignmentService). O encerramento/cancelamento reabre o Lugar de origem (origin_assignment_id em t_assignment).
