## 1. Arquitetura e Padrões Transversais

### 1.1. Visão Geral

O SIGDI adota microserviços desacoplados comunicando-se de forma síncrona (REST) para operações críticas de leitura/escrita e assíncrona (Kafka) para consistência eventual e notificações.

```
Frontend → API Gateway → [Service-Strategy, Service-Tactical, Service-Budget,
                          Service-Intelligence, Service-Compliance, Service-Admin]
                       → Kafka → [Service-Notification, consumidores internos]
                       → [SIGOF/PDEX, Autentika, BDRH] (sistemas externos)
```

### 1.2. Envelope de Resposta Padrão (JSend)

Todas as respostas bem-sucedidas seguem este envelope:

```json
{
  "status": "success",
  "data": { },
  "metadata": {
    "page": 0,
    "size": 20,
    "totalElements": 150,
    "totalPages": 8
  }
}
```

O campo `metadata` é incluído apenas em respostas paginadas. Respostas de criação retornam HTTP 201 com o recurso criado em `data`. Respostas de deleção retornam HTTP 204 sem corpo.

### 1.3. Erros — Problem Details (RFC 7807)

```json
{
  "type": "https://sigdi.gov.cv/errors/budget-exceeded",
  "title": "Saldo Orçamental Insuficiente",
  "status": 422,
  "detail": "O valor solicitado (65.000$00) excede o saldo disponível (50.000$00) para o classificador 02.02.01.",
  "instance": "/api/v1/tactical/activities",
  "errorCode": "SIGDI-BUD-001",
  "extensions": {
    "requested": 65000.00,
    "available": 50000.00,
    "classifier": "02.02.01"
  }
}
```

**Catálogo de códigos de erro:**

| Código | Status HTTP | Descrição |
| :--- | :--- | :--- |
| `SIGDI-BUD-001` | 422 | Saldo orçamental insuficiente |
| `SIGDI-BUD-002` | 422 | Classificador económico inválido ou inexistente |
| `SIGDI-TAC-001` | 422 | Data fora do ciclo PAA vigente |
| `SIGDI-TAC-002` | 409 | Atividade já aprovada — requer Change Request |
| `SIGDI-TAC-003` | 422 | Objetivo estratégico inativo ou inexistente |
| `SIGDI-WRK-001` | 403 | Utilizador sem permissão para aprovar neste nível |
| `SIGDI-WRK-002` | 409 | Atividade não está no estado esperado para esta operação |
| `SIGDI-SIA-001` | 422 | Quota de mérito excedida para a unidade orgânica |
| `SIGDI-SIA-002` | 422 | OKRs sem check-in final — avaliação incompleta |
| `SIGDI-STR-001` | 409 | Link causa-efeito criaria ciclo no grafo BSC |
| `SIGDI-ADM-001` | 409 | Instituição já existe com este código |
| `SIGDI-ADM-002` | 403 | Operação restrita ao Admin NOSi |
| `SIGDI-SEC-001` | 401 | Token inválido ou expirado |
| `SIGDI-SEC-002` | 403 | Acesso negado — perfil insuficiente |
| `SIGDI-GEN-001` | 404 | Recurso não encontrado |
| `SIGDI-GEN-002` | 409 | Conflito de versão (Optimistic Locking) |
| `SIGDI-GEN-003` | 503 | Serviço externo indisponível (SIGOF/PDEX) |

### 1.4. Autenticação e Autorização

Todos os endpoints exigem header `Authorization: Bearer {jwt_token}`.

**Claims obrigatórias no JWT:**

```json
{
  "sub": "uuid-do-utilizador",
  "institution_id": "uuid-da-instituicao",
  "roles": ["ROLE_TACTICAL_USER"],
  "name": "Carlos Silva",
  "email": "carlos.silva@min.gov.cv",
  "exp": 1743350400
}
```

**Papéis e permissões:**

| Role | Módulos Acessíveis | Restrições |
| :--- | :--- | :--- |
| `ROLE_NOSI_ADMIN` | Todos (cross-institution) | Gestão de instituições e configurações globais |
| `ROLE_INSTITUTION_ADMIN` | Todos (própria instituição) | Gestão de utilizadores e parâmetros da instituição |
| `ROLE_STRATEGY_MANAGER` | Strategy, Dashboard, Compliance (leitura) | Aprovação estratégica de PAA, BSC |
| `ROLE_TACTICAL_MANAGER` | Tactical, Budget (leitura), Workflow | Aprovação tática de PAA |
| `ROLE_TACTICAL_USER` | Tactical (escrita própria), Budget (leitura) | Criação de atividades e check-ins |
| `ROLE_FINANCIAL_AUDITOR` | Budget, Compliance (leitura), Audit Logs | Read-only em tudo |

### 1.5. Paginação e Filtros (Padrão)

Todos os endpoints de listagem aceitam os seguintes parâmetros de query:

| Parâmetro | Tipo | Default | Descrição |
| :--- | :--- | :--- | :--- |
| `page` | integer | 0 | Número da página (base 0) |
| `size` | integer | 20 | Itens por página (máx. 100) |
| `sortBy` | string | `createdAt` | Campo de ordenação |
| `sortDir` | string | `desc` | Direção: `asc` ou `desc` |

### 2.1. Identidade Institucional

#### `POST /v1/strategy/identities`
Cria uma nova versão (Snapshot) da Identidade Institucional. A versão anterior é automaticamente arquivada.

**Roles:** `ROLE_STRATEGY_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Request:**
```json
{
  "mission": "Garantir a excelência na prestação de serviços públicos aos cidadãos de Cabo Verde, promovendo o desenvolvimento sustentável.",
  "vision": "Ser referência nacional em gestão pública eficiente e transparente até 2030.",

  "versionComment": "Revisão anual 2026 — aprovada em Conselho Diretivo de 15/01/2026"
}
```

**Validações:**
- `mission`: obrigatório, mínimo 20 caracteres.
- `vision`: obrigatório, mínimo 20 caracteres.
- `values`: obrigatório, mínimo 1 item.

**Response 201:**

### 2.2. Objetivos Estratégicos

#### `POST /v1/strategy/goals`
Cria um Objetivo Estratégico no BSC da instituição.

**Roles:** `ROLE_STRATEGY_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Request:**
```json
{
  "title": "Aumentar a satisfação dos cidadãos com os serviços prestados",
  "description": "Melhorar a experiência do cidadão em todos os pontos de contacto, reduzindo o tempo médio de atendimento e aumentando o índice de satisfação.",
  "perspective": "CUSTOMER",
  "weight": 2.0,
  "parentGoalId": null
}
```

**Validações:**
- `title`: obrigatório, mínimo 5, máximo 255 caracteres.
- `perspective`: obrigatório, valores: `FINANCIAL`, `CUSTOMER`, `PROCESS`, `LEARNING`.
- `weight`: obrigatório, entre 0.1 e 10.0, incremento de 0.1.
- `parentGoalId`: opcional. Se fornecido, o objetivo pai deve estar ativo e pertencer à mesma instituição.

**Response 201:**
```json
{
  "status": "success",
  "data": {
    "id": "goal-uuid-0001",
    "institutionId": "inst-uuid-0001",
    "title": "Aumentar a satisfação dos cidadãos com os serviços prestados",
    "description": "Melhorar a experiência do cidadão...",
    "perspective": "CUSTOMER",
    "weight": 2.0,
    "status": "ACTIVE",
    "progress": 0.0,
    "parentGoalId": null,
    "childGoals": [],
    "linkedActivities": 0,
    "createdAt": "2026-01-20T14:00:00Z",
    "createdBy": { "id": "user-uuid-001", "name": "Ana Monteiro" }
  }
}
```

**Erros possíveis:**
- `SIGDI-STR-001` (409): se `parentGoalId` está inativo.
- `SIGDI-GEN-001` (404): se `parentGoalId` não existe.

---

**Roles:** Todos

**Response 200:**

```json
  "data": [
    {
      "id": "goal-uuid-0001",

      "perspective": "CUSTOMER",

  ],
```

---

#### `PATCH /v1/strategy/goals/{id}`
Atualiza campos de um objetivo estratégico. Apenas `title`, `description` e `weight` são alteráveis. `perspective` é imutável após criação.

**Roles:** `ROLE_STRATEGY_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Request:**
```json
{
  "title": "Aumentar a satisfação dos cidadãos — meta revista",
  "description": "Descrição atualizada.",
  "weight": 3.0
}
```

**Response 200:** Retorna o objetivo completo atualizado (mesma estrutura do POST 201).

---

#### `DELETE /v1/strategy/goals/{id}`
Cancela (soft delete) um objetivo. Não é permitido se existirem atividades PAA ativas vinculadas.

**Roles:** `ROLE_STRATEGY_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Response 204:** Sem corpo.

**Erros possíveis:**
- `SIGDI-TAC-003` (422): existem atividades aprovadas vinculadas.

#### `POST /v1/strategy/map/links`
Cria uma relação causa-efeito entre dois objetivos.

**Roles:** `ROLE_STRATEGY_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Request:**
```json
{
  "sourceId": "goal-uuid-0002",
  "targetId": "goal-uuid-0001",
  "relationshipType": "CAUSE_EFFECT"
}
```

**Validações:**
- `sourceId` e `targetId` devem existir, estar ativos e pertencer à mesma instituição.
- O link não pode criar um ciclo no grafo.
- O link não pode ser duplicado.

**Response 201:**
```json
{
  "status": "success",
  "data": {
    "id": "edge-uuid-001",
    "sourceId": "goal-uuid-0002",
    "targetId": "goal-uuid-0001",
    "relationshipType": "CAUSE_EFFECT",
    "createdAt": "2026-01-20T14:30:00Z"
  }
}
```

**Erros possíveis:**
- `SIGDI-STR-001` (409): link criaria um ciclo no grafo.
- `SIGDI-GEN-001` (404): objetivo de origem ou destino não encontrado.

---

#### `DELETE /v1/strategy/map/links/{id}`
Remove uma relação do mapa estratégico.

**Roles:** `ROLE_STRATEGY_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Response 204:** Sem corpo.

### 3.1. Atividades PAA

Cria uma nova atividade no PAA. Valida saldo orçamental em tempo real via Service-Budget.

**Roles:** `ROLE_TACTICAL_USER`, `ROLE_TACTICAL_MANAGER`, `ROLE_INSTITUTION_ADMIN`

**Request:**
```json
{

  "organicUnitId": "unit-uuid-001",
  "title": "Formação em Atendimento ao Público",

  "endDate": "2026-03-03",
  "fiscalYear": 2026,
  "budget": {
    "estimatedAmount": 75000.00,
    "economicClassifier": "02.02.01",
    "driverType": "MANUAL"
  }
}
```

- `strategicGoalId`: deve existir, estar ativo e pertencer à mesma instituição.

- `endDate >= startDate`.
- `budget.estimatedAmount > 0`.
- `budget.economicClassifier`: deve existir no Plano de Contas Oficial.

## 9. Estratégia de Testes e Governança

### 9.1. Níveis de Teste

| Nível | Ferramenta | Cobertura Mínima | Foco |
| :--- | :--- | :--- | :--- |
| Unitários | JUnit 5 + Mockito | 80% global, 100% em cálculos SIADAP e progresso OKR | Domain Services, cálculos de negócio |
| Integração | SpringBootTest + Testcontainers | Todos os endpoints documentados | Controllers, Repositories, Jobs |
| Contrato | Pact (Consumer-Driven) | 100% das integrações cross-service e SIGOF | Contratos de API entre serviços |
| Multi-tenancy | Suite dedicada | 100% dos endpoints com dados cross-tenant | Isolamento de dados entre instituições |
| Carga | k6 | p95 < 2s sob 200 VUs simultâneos | Service-Tactical, Service-Budget |
| Segurança | OWASP ZAP (DAST) | OWASP Top 10 | Todos os endpoints expostos |

### 9.2. Critérios de Bloqueio do Pipeline CI/CD

O deploy em staging ou produção é bloqueado se:
- Cobertura de testes unitários < 80% em qualquer serviço.
- Qualquer teste de contrato Pact falhar (especialmente o contrato SIGOF).
- SonarQube reportar vulnerabilidades de severidade `CRITICAL` ou `BLOCKER`.
- Qualquer teste de isolamento multi-tenant falhar.

### 9.3. Versionamento de API

- Versionamento por URI Path: `/api/v1/...`, `/api/v2/...`.
- Descontinuação: header `X-API-Deprecation-Date` com aviso prévio de 3 meses.
- Backward compatibility garantida dentro da mesma versão major.

### 9.4. Governança e Code Review

**Checklist de Code Review:**
- [ ] Lógica de negócio está no Domain Service, não no Controller.
- [ ] Todos os endpoints têm anotação de autorização (`@PreAuthorize`).
- [ ] `institution_id` do JWT é sempre usado para filtrar queries — nunca parâmetro do cliente.
- [ ] Operações de escrita geram registo de auditoria.
- [ ] Erros retornam Problem Details com `errorCode` do catálogo definido neste documento.
- [ ] Queries JPA não têm problema N+1.
- [ ] Campos sensíveis não são logados.
- [ ] Nenhum segredo está hard-coded.
